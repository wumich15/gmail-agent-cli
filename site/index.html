X-Section: what one run does

Aggressive about bulk mail. Careful about everything else.

"A machine sent it" is not the same as "you don't need it." Receipts, security alerts, travel changes, appointment confirmations and deadlines are automated too, and they're the mail most worth protecting. So the cleanup is deliberately lopsided: obvious bulk goes fast, anything ambiguous is left alone and reported.

Trash
Promotions, newsletters you never open, and Gmail's own spam — moved to Gmail's Trash, where you can pull any of it back.
Star + Important
Mail that asks you a question, names a deadline, or concerns your money, security, or travel.
Calendar
An explicit, future, unambiguous date becomes a private event on your own calendar. No guests, no invitations, no duplicates.
Labels + archive
Topical labels once enough messages in a run agree on one, and every read message that survived gets out of the inbox.
Review
Anything uncertain: no trash, no star, no event. It stays where it is and appears in the summary.

Fixed rules, not preferences

  • It never permanently deletes mail. Trash only — the permanent-delete endpoints are not called anywhere in the code.
  • It never sends an email you haven't seen. Every outbound path — manual, AI-drafted, reply, unsubscribe — ends at the same screen showing the exact recipient, subject and body, defaulting to no.
  • It never follows instructions inside an email. Message text is evidence, never a command, and the model gets no tools, no network and no credentials.
  • It never uploads attachments — it doesn't even download them.

X-Section: where your mail goes

Two connections, both yours.

There is no service in the middle to trust, bill you, get breached, or shut down. The tool talks to Google with an OAuth client you registered, and — only if you turn AI on — to OpenAI with a key you own. Nothing is relayed through anyone else, because there is no one else.

What stays on disk: message IDs, labels, dates, senders, content hashes and an action ledger, in a SQLite file only your user account can read. Message bodies are never written to it — reading a message fetches it live.

What leaves, if AI is on: the sender, subject, date and a bounded plain-text excerpt of the message being classified. Calls set store: false. That's not a promise of zero retention at the provider, and the tool says so before you choose.

X-Section: setup

Ten minutes, once per computer.

The cost of having no middleman is that you register the Google app yourself. It's free, it stays private to you, and it means your mail is reachable only with your own credentials.

  1. Install it

    # Node.js 22.19+ and pnpm git clone <repo> gmail-agent-cli && cd gmail-agent-cli pnpm install --frozen-lockfile pnpm build pnpm link --global

  2. Register your own Google app

    In the Google Cloud Console: create a project, enable the Gmail API and Calendar API, add yourself as a test user on the consent screen with exactly two scopes — gmail.modify and calendar.events.owned — then create an OAuth client of type Desktop app.

  3. Connect and choose how AI works

    gmail setup # or: gmail ui — the same thing as a local page in your browser

    Paste the client ID and secret, sign in through Google in your browser, then pick your OpenAI key or no AI at all. Rules-only is a real mode: spam cleanup, your own rules and archiving read mail all still work.

  4. Look before you leap

    gmail --dry-run --limit 25 # reads mail, changes nothing, prints the plan gmail

And a mail client, while you're in there.

gmail view browses the local cache, opens messages as bounded plain text with clickable links, and composes or replies — by hand or with an AI draft you edit before it goes anywhere.
