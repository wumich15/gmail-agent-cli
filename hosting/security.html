Security

How Gmail Agent is built to fail safe, and how to report a problem.

Reporting a vulnerability

Email [Security contact address]. Please include enough detail to reproduce the issue. We aim to acknowledge within [Acknowledgement SLA] and will keep you updated until it is resolved. Please do not test against mailboxes you do not own.

Credentials

  • Google refresh tokens and the included-AI session token live in your OS credential store (Keychain, Credential Manager, or Secret Service), never in a config file, the database, a log, or a command-line flag.
  • Access tokens are held in memory only.
  • Sign-in uses the OAuth installed-app flow with PKCE S256, a random state, an OIDC nonce, and a loopback listener bound to 127.0.0.1 on a random port. There is no copy/paste flow and no embedded browser.
  • The service holds no Google credential of yours and cannot call Gmail on your behalf.
  • Any model-provider key exists only in Google Secret Manager, bound to the gateway runtime. It is never returned to a client.

Scopes

Gmail Agent requests gmail.modify and calendar.events.owned, plus openid when the included AI is available so the service can authenticate you without ever seeing your address. It does not request full mail access, Gmail settings, Drive, or Contacts, and it never calls Gmail’s permanent-delete endpoints.

Untrusted content

Email is treated as data, never as instructions. The model has no tools, no network access, no credentials, and no ability to act; it returns a typed assessment that deterministic code on your computer turns into actions. Instructions and content are kept in separate parts of every request, with an explicit direction to ignore anything in the content that reads as a directive. A date the model claims is verified against the message text before any calendar event is created, and a suspicious classification never produces an automated action.

The gateway

  • Two typed operations, with closed schemas and hard input bounds. No model name, tool, provider URL, or unknown field is accepted from a caller.
  • Every request requires a verified session and a current, non-revoked consent receipt.
  • Per-user quotas are reserved atomically before any paid call; instance counts and concurrency are capped; a global switch disables the service without a redeploy.
  • Logs record operation, pseudonymous identifier, status, duration, and token counts — never content, tokens, addresses, or raw provider errors.

What this design does not claim

The CLI is open source and its OAuth client configuration is necessarily public, so we cannot prove a given request came from an unmodified build. That is why the real boundaries are the narrow request schema, the consent gate, the quota, and Google’s own consent screen — not client integrity.
